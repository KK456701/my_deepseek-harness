# Agent Note: Profile-scoped long-term memory

Status: proposed

English | [中文](2026-09-01-profile-long-term-memory.zh.md)

## Problem

An interactive Session retains its own durable history, but a later Session cannot reuse stable preferences, verified procedures, failure corrections, or user-requested memory without reopening old conversations. Copying full histories into every request is expensive and unsafe because historical evidence may be stale, secret-bearing, or externally sourced, while current instructions and current tool results must remain authoritative.

The feature also needs recoverable background model calls, inspectable final memory, cross-process publication safety, explicit remember/update/forget semantics, and a management UI. A database-only knowledge store would hide the layered model-facing material, while mutable Markdown alone cannot provide leases, audit ordering, retry state, reset watermarks, or stale-writer fencing.

## Proposal

Add an opt-in long-term-memory capability to each resolved DSH profile, with extraction, consolidation, and recall semantics fixed to Codex commit `eb10d91e48ccbd0930427461fb392337addb1ac0` plus the DSH publication and management safeguards in this note. A private SQLite State database coordinates source ranges, policy generations, leases, retries, audited model calls, explicit notes, usage, and publication. An immutable generation directory is the final model-visible knowledge base: `memory_summary.md` is the high-density prompt layer, `MEMORY.md` is the searchable task-group layer, `skills/` contains repeated verified procedures, and backend-owned rollout files retain task evidence. An atomic `current.json` pointer selects one fenced generation.

The capability has three internal ownership layers. `memory-local` provides public `MemoryService` and private `MemoryPipelineStore`; it alone owns SQLite, private audits, staging, manifests, Git baselines, generations, locks, and the pointer. `memory-scheduler` consumes the private Store plus Agent, Session, LLM, and Jobs services and provides `MemoryMaintenanceService`; it performs discovery, evidence freezing, extraction, consolidation, retry, and quiescent shutdown without importing storage implementations. `memory-maintenance-triggers` consumes the maintenance service and translates provider startup, interactive root Session startup, deadlines, controls, manual scan or consolidation, and durable non-note work events into coalesced wakeups. Prompt, Remote, and UI consumers use only `MemoryService`.

Automatic extraction follows later-Session scheduling: interactive turn completion flushes the Session without waking memory work, while creation or resume of a later interactive root Session wakes bounded discovery of sufficiently idle older Sessions. The management UI separates two explicit operations. Manual scan runs bounded discovery while ignoring only the configured idle delay; it still excludes active, unsafe, too-short, too-old, or non-contributing Sessions and continues discovered ranges through Phase 1 and Phase 2. Manual consolidation skips discovery and consumes only durable candidates and explicit notes. An explicit remember, update, or forget operation immediately persists an active pending ad-hoc note, skips Phase 1, and waits for the next normal Phase 2 wake. Note creation never starts a model call implicitly and does not claim publication before a new generation commits.

Phase 1 works on one complete eligible interactive Session rollout rather than treating each turn as an independent source. It freezes the effective surface through the last completed root turn, excludes fork seeds and shadowed replacements, pairs tool calls with effective results, and preserves multiple tasks in one Stage 1 result. Secret fields are redacted before the exact request is audited and model output is scanned again before Stage 1 is stored. A zero-memory result is successful and advances source progress.

Phase 1 preserves task outcome, scope, evidence ids, approximate user wording, repeated steering, interruptions, redo, narrowed scope, failed actions, replacements, commands, paths, APIs, environment conditions, and verification. It records evidence without assigning an irreversible promotion tier; short meaningful corrections are admitted on the same terms as longer messages. A weak next-step signal remains task evidence rather than becoming a global preference, and an interruption or redo first becomes a failure shield. Phase 2 performs a preference-first pass across every rollout: semantically consistent independent evidence raises confidence without exact-string matching, newer same-scope explicit evidence can update older evidence, different scopes may coexist, and unresolved conflicts remain formal detailed memory without becoming an injected default. Promotion creates denser linked representations without deleting lower-level evidence. A Skill requires a repeatable, actionable procedure with reliable evidence from at least the configured `skillMinSupportingTasks`; a verified correction may support a failure-shield Skill even when an earlier attempt failed.

The Codex backend uses a private `CodexStructuredRunner` provided by the app-server integration. Both phases pass a frozen model, reasoning effort, prompt, and JSON schema per call without changing global Codex settings. Phase 1 returns task-level evidence; Phase 2 returns complete summary/manual/skill files, source decisions, and one disposition per claimed note. The Store audits the exact app-server request before dispatch and the final structured result before application, then materializes and validates files itself. Calls use an empty temporary directory, read-only sandbox, unattended approval policy, and disabled optional tool features. Any observed tool item rejects the attempt; this observer does not prove that an upstream tool never executed. Commentary and reasoning are not retained. The existing LLM backend remains selectable and uses its private maintenance Session for tool-based consolidation.

`memory_summary.md` has `User Profile`, `User preferences`, `General Tips`, and `What's in Memory` sections under a fixed byte budget. Every summary list item contains an actual relative Markdown link; plain filenames and prose references are rejected. `MEMORY.md` starts with `# Memory` and uses top-level `# Task Group:` blocks whose task sections contain linked rollout files and grep-oriented keywords. Generated links form a backend-validated source graph; `generation-manifest.json` records hashes, headings, line ranges, and transitive source ids. Source-selection diffs support best-effort local forgetting: content supported only by removed automatic sources is deleted, retained support keeps the content, active explicit notes remain authoritative, and removed sources cannot appear in the published manifest.

The provider derives user-manageable semantic items from the verified Markdown and manifest rather than exposing arbitrary lines. Profile, preference, and general-tip bullets plus complete Task Groups are revision-safe targets. Update and delete requests carry the generation, line range, and content hash, create structured explicit notes, and immediately suppress the old item from prompt and recall while Phase 2 prepares the next immutable generation. Skills, rollout evidence, raw memory, and manifests remain read-only.

Public controls separate reading from contribution. `use` controls summary injection and `memory_list`, `memory_search`, and `memory_read`; `contribute` controls automatic Phase 1 registration. Every interactive Agent advertises `memory_update_request` because prompt assembly precedes current-inbox admission; at execution, trusted runtime code requires a matching explicit remember, update, or forget action in the current logged user message and binds its Session, turn, and user-event identity. `forget` remains available when recall is denied, reset is never model-autonomous, and disabled profiles retain management and deletion access. Processing state and continuing authority are independent, so applied remember notes and forget tombstones remain active until superseded, cleared, or reset.

The read path injects only a leased, byte-bounded summary and narrow recall tools. The exact prompt section enters `request/header`. A Recall Gate skips self-contained requests, performs a quick lexical pass for historical decisions or ambiguity, and permits one second pass after a familiar error, scope change, or repeated failure. Runtime counters enforce per-turn pass, tool-call, and distinct-detail limits. Memory is untrusted and potentially stale: existing DSH instruction precedence governs instructions, current task constraints outrank historical preferences, and current code or tool output outranks remembered facts.

Runtime settings use optimistic revisions and apply to the next turn or claim without a restart. Backend, model, and reasoning effort are frozen per attempt. Template identity participates in extraction fingerprints and manifests. A confirmed clean rebuild raises the epoch, clears the pointer and derived state, and retains original Session logs, controls, settings, and reset watermarks. Its persisted completion cutoff comes from the requested lookback, defaulting to five days; older turns in recent Sessions are not evidence. `explicitNotePolicy` either preserves active notes and tombstones or purges all of them. Rebuild bypasses idle and age admission, waits for active Sessions, and exposes no partial generation. User reset instead writes `clearThroughSeq` to prevent relearning pre-reset history. Output-budget exhaustion and validation failures cannot publish partial files; retries use clean staging.

The optional `disableOnExternalContext` guard defaults to false, matching Codex's documented default. A classified external result remains untrusted evidence with its original role; it does not disqualify adjacent direct user messages unless the guard is enabled. Both settings use the same audited extraction pipeline. Explicit management has a stable prompt section even when recall is disabled or empty, and acknowledgment follows a successful save result. Summary selection considers future behavioral value as well as evidential support: isolated installation facts and script caveats belong in detailed memory when useful, not automatically in the profile or general tips. Future-facing forms of address are preference evidence, not one-time greetings.

Request-level visibility uses a non-model-visible observation linked to the actual persisted header at dispatch, not a synthetic tool call or an assembly-success marker. Repeated summaries reuse the header body. Whole-item Markdown selection bounds each injection without altering published generations or invalidating them on writing-template changes. Explicit conversation notes preserve redacted genuine user wording separately from the model draft; original wording constrains scope, negation, frequency, and placement during later consolidation. Semantic fidelity remains a model acceptance criterion, not a database-proven equivalence. Missing historical originals remain unavailable unless their bound Session event can be verified. The schema upgrade is offline and backup-first; it does not re-extract memory, change scheduling, or add a background-process panel.

Extraction uses bounded independent workers, while consolidation waits for their completion and selects from all valid Session sources using citation feedback. Raw task evidence and rollout summaries are independently authored artifacts. Persisted complete input sets prevent model discard decisions from causing repeated consolidation; usage ranks choose inputs, not summary or handbook layout. Cards render each body once and expose source counters without conflating them with exact item usage. Incremental backed-up upgrades preserve existing memory and extraction receipts; new request formats do not trigger historical extraction.

## Alternatives considered

**A separate user-intent-only extraction pipeline.** Rejected because the optional guard and existing role-aware, redacted evidence projection preserve direct requests without adding another lifecycle. Quoted user material and external results still require semantic attribution; neither becomes user intent solely by being present in the transcript.

**Change global Codex model settings.** Rejected because extraction and consolidation need independently frozen model and reasoning settings per call. The deployment selects supported models and efforts without changing other Codex tasks.

**Always rebuild all retained history.** Rejected for a time-bounded rebuild. The confirmed operation records an immutable completion-time cutoff, defaulting to five days, and excludes earlier turns even within a recent Session. The user separately chooses whether to preserve active explicit notes or purge all notes and tombstones. Original Sessions, controls, settings, consent, and reset watermarks remain intact. Empty extraction leaves only an internal receipt; source decisions exclude unhelpful evidence files from publication.

**Use SQLite as the final knowledge store.** Rejected because model-facing memory needs inspectable, linkable, grep-friendly layers with different compression levels. SQLite remains the coordination and recovery store.

**Use mutable Markdown as the only store.** Rejected because audit-before-dispatch, multi-process claims, reset watermarks, note authority, atomic publication, and crash recovery require transactional state.

**Let ordinary filesystem tools read the memory root.** Rejected because dedicated list/search/read tools make `use=deny`, root authorization, deterministic limits, citation telemetry, and model-visible tool discovery enforceable.

**Automatically turn one observed behavior into a preference.** Rejected because task-local instructions and weak inference are not durable user intent. Explicit future-facing requests may promote once; ordinary inference requires repeated compatible evidence.

**Scope memory by workspace inside one profile.** Rejected for this capability. A profile is the isolation unit; workspace identity remains provenance and relevance metadata.

**Allow Phase 2 to rewrite rollout evidence.** Rejected because immutable evidence is required for source accounting, local forgetting, citations, and user inspection.

## Acceptance criteria

- Independent extraction workers obey concurrency and claim bounds; one failure does not cancel peers. Source selection reuses high-use consumed outputs, skips unchanged sets, and retains notes outside automatic capacity. Pruning respects publication, leases, and receipts. Migration preserves current files and dispatches no historical extraction; UI tests verify single rendering and per-source cross-process feedback.
- Service definitions, providers, consumers, and the Loader graph preserve the three ownership layers without dependency cycles; scheduler source imports no SQLite, pointer, Git, or generation implementation.
- Phase 1 accepts multiple tasks, redacts secrets without discarding safe content, audits before dispatch/apply, and advances an empty result.
- Mixed external/user ranges dispatch normally by default and are excluded only with the guard enabled. Explicit requests save despite disabled recall; storage errors cannot produce success receipts. Real conversations verify the saved note and its user-event provenance, not just an assistant's verbal acknowledgment.
- Codex attempts reject observed tools and require complete structured source/note partitions; the LLM backend confines its five tools to staging. Neither backend can publish without canonical Task Groups, summary links, source closure, and ownership checks.
- Summary, Task Groups, skills, and rollout evidence retain linked representations at their intended compression levels; summary overflow removes complete low-value items.
- `use=deny` hides injection and recall tools while explicit management remains available; `contribute=deny` prevents automatic source registration; disabled memory remains viewable and resettable.
- Interactive root Session startup wakes maintenance; ordinary turn completion only flushes. Manual scan bypasses only idle time and retains every other eligibility check; manual consolidation performs no discovery. Explicit notes remain pending without a model call until later scheduled work or a user-requested consolidation.
- Recall limits are enforced per turn, citations update source usage, and replay uses the logged prompt section rather than current disk state.
- Expired sources produce a removal diff; retained or explicit support prevents over-deletion. A preserve-active rebuild keeps explicit authority; reset prevents rediscovery of old ranges.
- A clean rebuild deletes old derived sources, candidates, audits, jobs, failures, staging, and generations. It preserves Sessions, controls, and reset watermarks, applies the chosen note policy, persists its cutoff through restart, and excludes older turns before evidence projection.
- Normal discovery applies the configured age limit to individual completed turns, not only the Session's latest activity. Reset watermarks trim old prefixes even when the same Session gains a new turn.
- Semantic-item update and delete reject stale generation or content hashes, suppress pending old content immediately, and become durable only through a verified new generation.
- Token-budget exhaustion reports its category, configured limit, and attempt count, and cannot publish a partial generation; operation timeout cancels a live maintenance Agent and records a retryable provider timeout.
- Fencing prevents old owners from publishing; private one-shot and maintenance audits reconstruct every background model call; disposal waits for owned work to settle.
- Unit, backend, real Loader, keyless snapshot, Web component, optional provider, and real browser-flow coverage exercise the assembled capability.

## Risks

One profile intentionally shares memory across its workspaces. Users needing stronger isolation must use separate profiles.

Provenance links prove which evidence a generated statement cites, not that the model interpreted evidence correctly. Natural-language consolidation and partial forgetting remain best effort, while manifest integrity, removed-source exclusion, leases, and publication fencing are code-enforced.

Secret detection is pattern-based and can miss unknown formats. Published generations are rejected on detected secrets, but original Session retention remains owned by the Session subsystem.

SQLite files, WAL pages, backups, and original Session logs are not encrypted or immediately physically erased by logical deletion. Product documentation must describe this limit.

Manual scan can dispatch model work for a recently completed Session sooner than automatic scheduling. It remains a deliberate user action, uses the same bounded scan and claim limits, and never takes maintenance ownership from an active Agent. Clean rebuild is more expensive because it deliberately ignores ordinary age and idle admission limits for retained Sessions; its durable progress and empty-current state make that cost and availability impact explicit.
