# Agent Note: 需求连续性与交付审查

Status: proposed

[English](2026-09-03-retained-intent-and-delivery-control.md) | 中文

## 问题

长任务可能遗失早期问题，在用户纠正后继续沿用旧需求，反复调查却没有新证据，或提交语言流畅但漏答、夸大结果的回答。仅靠对话历史无法提供稳定的需求身份，也没有一个可以机械拒绝不完整交付的位置。

## 提案

实验审查 Bundle 只使用三个辅助模型节点和一个确定性的执行控制提供方：

1. 需求变更解析仅在存在新用户消息时、Worker Step 前运行。模型只建议 `add`、`revise` 和 `cancel` 的语义；可以独立回答或验证的子问题保留为不同变化，实际检查或核实即使最终交付文字报告也使用 `execution`。运行时把每项有效变化绑定到当前完整用户消息，校验目标身份和调用前捕获的 ledger revision，再追加格式版本 3 的更新。Web 实验装配对该解析器使用 Low 推理、4,096 Token 输出上限和 30 秒超时；Reviewer 与 Observer 继续使用 High。
2. Progress Observer 在出现三次完全相同的调用／结果对、三个相邻任务工具失败、结果不变的 `A-B-A-B-A-B` 排列，或真实执行五分钟且至少产生三个任务工具结果后运行。审批等待、执行暂停和 Observer 自身耗时不计入真实执行时间。初始请求只携带选中 Session Event 的精简索引；Observer 需要完整细节时，复用 Final Reviewer 的冻结只读适配调用 `session_event_search/read`。Observer 只返回是否有进展、最重要的风险、证据事件 ID 和简短原因。每次调用绑定触发时的需求和输入版本；后续输入只会使结果过期，不会用新需求重新审查旧工作。
3. Final Reviewer 在 Enforce 模式下先暂存候选，再在普通 `assistant/message` 交付前逐项核对所有未取消需求（包括已完成项）的确切版本、最新正式批准计划原文、成功结果事件、回答段落和缺少证据的完成声明。审查不通过时，候选不会进入普通 Worker 历史；同一个 Turn 进入受限改写、有限补做或重新规划。Shadow 无法拦截消息，因此仍在交付后观察。

TaskExecutionControl 负责暂停和补救预算，但不调用模型，也不替代 DSH 现有沙箱、审批策略或工具 Guard。append-only 需求清单仍是权威数据。启用后，精简 Worker 快照按待完成、已完成和已取消分组，并附上用户正式批准的完整计划；不发送来源坐标、事件 ID、证据 ID 和历史版本。内容未变化时不重复追加；压缩遮蔽当前快照后，下一次请求会重新注入。

重新规划与结果未知挂起会把受影响 Agent 绑定到部署中解析到的 Plan Mode Controller。解析顺序为 Agent Context、由 AgentPresets 隔离域发布的 Controller、根 Context；持久 Plan Mode 状态仍按 Session 隔离。TaskExecutionControl 观察该 Controller 的计划审批，展示前捕获需求与执行 revision，只在确切的正式批准通过这些校验后恢复 `running`。普通问题回答和模式切换都不会解除挂起。

## 需求状态

工具派发成功与命令成功不同。Reviewer 版本 8 在选定结果事件中保留对应调用身份，并与 Observer 失败检测复用现有 Shell 退出状态解析。非零退出和信号终止不能支持已验证完成；后台启动或缺失调用记录时，完成状态未知。初始模型输入仍只含结果定位索引，不额外复制调用正文。本实现复用已有 Session 事件，不新增审计格式。

每条当前需求只包含稳定 ID、内容版本、当前正文、`answer` 或 `execution` 验证方式、精确用户来源、生命周期状态和完成证据。修改需求时保持 ID、增加版本、重新打开需求并清除旧版本的完成结论；取消只改变状态，不删除历史。旧版本由 append-only Session Event 保留。

正式计划直接来自 `plan/review-approved`，不再调用计划验收项提取模型。未经批准的助手建议仍只是普通对话内容。Reviewer 可以指出遗漏的必要计划原文，但运行时必须验证该原文确实存在于批准计划中。

## 进展与交付

进展是与开放需求有关的新证据：获得新结果、支持或推翻重要假设、产出并验证目标成果、缩小故障范围、解除阻塞，或回答尚未回答的问题。命令成功但没有新增相关信息、文件修改没有证据表明服务于当前需求、构建成功却没有复现用户实际问题、只描述下一步、重复相同材料，或换命令继续验证已被否定的假设，都不算进展。

精确重复由程序确定：工具名、规范化参数和最终结果或错误必须一致，并且中间没有新的真实用户消息。第三个相同调用／结果对结束后追加提醒；未改变的第四次调用由 `ctx.tools.guard()` 在工具实现启动前拒绝。随后由语义 Observer 判断应换方案、说明阻塞还是重新规划。三个相邻失败和结果不变的 `A-B-A-B-A-B` 也会触发 Observer；`off-track` 和 `critical-assumption` 判断会立即暂停。现有工具执行链负责落实这些限制。

时间窗口从当前 Turn 开始、带真实用户来源的需求更新、正式计划批准或上次有效 `progress=yes` 开始。真实执行满五分钟且至少完成三个任务工具结果后，下一个结果触发检查。有效 `yes` 必须引用窗口中的真实 `tool/result`；带来新诊断事实的失败结果也可证明进展。调用事件只能证明派发，会被拒绝并允许一次有界修复。有效 `yes` 重置窗口；`no` 立即暂停；`uncertain` 再运行五分钟后复查，连续十分钟仍未确认进展则暂停。任一明确风险无论 progress 取值如何都暂停。

单 Turn 任务工具保险丝继续可配置，默认值为 80。Worker Step 数和普通 Turn 时长不设总上限，语义无进展由 Progress Observer 判断。

最终审查分别判断回答覆盖和工作验证。只需文字回答的需求必须定位到回答段落；执行型需求还需要成功结果证据。用户明确询问进度时的中间回复，或如实的真实阻塞，可以结束本轮但不关闭需求；Worker 自行编写的进度汇报不能结束用户要求完整交付的工作。只漏说明时进入禁用任务工具的改写；缺少仍在授权范围内的工作时可以在补救预算内继续；过度声明、无效证据、方向改变或需要新授权时进入交付修复或暂停重规划。修复通过后会解除临时执行限制。

由 TaskExecutionControl 自身暂停通知触发的回复可以在任务工具仍暂停时接受最终审查。该例外由已领取的插件消息确定，不能由 Worker 正文声明。候选失效时必须先提供新的 next-Step 输入，Agent Loop 才继续。

每 Turn 的 Candidate 次数配额只统计最终回答尝试。工具调用 Step 仍受 staging 字节预算约束，但不占用最终回答次数；否则普通调查可能在到达 Final Reviewer 前失败。

单个候选、每 Turn 和每 Session 的 staging 字节上限都按组装后的候选内容计算，不重复统计 Provider 分段包装。相邻候选增量在持久化前有界合并；完整内容仍可回放，Provider 的 chunk 粒度不能改变事件数量或容量判断。

程序校验 Requirement、段落、事件、版本和计划引用是否真实一致，但不声称能证明自然语言蕴含关系；语义判断能力仍须通过独立评测验证。

## 审计与轨迹

输入接收回执在真实用户消息进入历史后的 `agent/request-starting` 写入，不在 Session 事件发布期间重入追加。冻结结果定位只含身份、状态、工具名和可选有界目标提示，不含结果预览；完整读取一并返回结果正文与原始调用参数。Observer 每个调用／结果对只列一次，原始事件仍可查询。Parser 合并重叠规则，不删除用户原文或改变输出 Schema。校验修复沿用已读证据、查询额度和原截止时间，不重复失败推理。完整对话的测试标记仍使用正常对话位置；缺失验收结论保持未记录，不能由 Turn 结束推断通过。

每次真实辅助模型派发都持久记录 call identity、角色、模板和输入投影版本、生命周期位置、Provider 输出、终态响应、校验结果，以及 Provider 报告的用量和时间。需求解析的投影版本 12（解析输入版本 5）只包含当前一条用户消息、精简的未取消需求和存在时的一份最新正式批准计划；来源与完成证据不进入模型输入。Final Reviewer 版本 8 和 Observer 初始请求都只携带冻结证据索引；其作用域内的 `session_event_search/read` 复用同一适配，只读取调用方授权的事件集合，不进入普通 Worker 工具目录，也不生成任务工具事件。Observer 对 Provider 公布封闭的四字段响应 Schema，并在校验这四个自有字段前丢弃无害的额外顶层元数据；非自有元数据不能影响执行控制，也不会把合法判断变成执行暂停。轨迹把需求变更解析放在对应 Step 前，把 Observer 放在触发结果之后，并把 Enforce Final Reviewer 放在正式交付之前。定向筛查使用 evaluation 位置，不伪造普通 User、Tool 或 Assistant 事件。Provider 返回的推理可查看，但不会进入 Worker 历史。

Reviewer 请求告知配置的证据查询上限。无工具的收束请求只包含一份冻结输入和已收集结果数据，不携带助手推理及工具已不可用的原生调用历史。DeepSeek 请求 JSON-object 最终正文，但不降低推理档位。只有思考而无正文仍是校验失败，不能作为已接受结论。原始截止时间、查询额度和一次修复限制仍然有效；未解决缺口不能变成通过结论。

旧的提取、多任务、计划检查和模型授权记录仅作为历史审计数据继续读取，新代码不再生成。精简任务快照从当前需求事件派生，使用普通 snapshot-form 上下文消息，不新增事件类型。DSH 现有沙箱、审批和工具 Guard 仍是权限控制的权威实现。

进入 next-Step 的真实用户插话会阻止旧请求所有尚未启动的任务工具，包括只读和嵌套调用。实际工具入口在审批和持久化后再次检查输入领取状态；被拒绝的工具不在内部等待，而由下一 Step 解析输入。恢复时，已保存消息必须有解析成功记录才能视为已处理。

证据新鲜度复用派发、结果、观察到的文件版本和保守工作区修改检查。被拒绝且未启动的调用不算修改；已启动但结果未知仍按可能修改处理。普通命令验证不建立文件依赖图，也不覆盖未观察到的远端变化。完成情况未知时先只读核验，影响不确定的调用需要精确单次审批；有依据的缺失或错误才定点补救。所有补救路径共用原预算。

回答覆盖引用候选中的精确片段。正式批准保留需求版本基线，后续内容变更会标记计划待核对，但不能恢复取消项。可信活跃目标轮询由 Guard／Observer 共享策略排除机械重复，不排除语义观察。确定性检查只证明程序规则，不证明模型准确率。

## 考虑过的替代方案

以下资料仅用于借鉴机制，不引入框架依赖或复制实现。OpenHands 用于参考结果感知重复检测与提醒去重，Magentic-One 用于参考结合事实重新规划，DeepAgents 用于参考精简上下文但保留原文可达性，τ²-bench 用于参考环境结果与回答分开评分。它们都不能证明本方案的长任务准确率。

**继续使用 High 推理和更大的解析输出预算。** 解析器只需判断三类变化并返回紧凑 JSON。Low 推理和 4,096 Token 上限限制分类输出；Reviewer 与 Observer 分别配置推理强度。

**让模型返回用户消息 ID 和文本范围。** 这会把运行时已知的来源控制权交给模型。运行时改为把每项有效变化统一绑定到当前完整用户消息，并使用调用前捕获的 ledger revision 拒绝迟到结果。

**不向解析器提供已批准计划。** 这样能减少输入字节，但会导致“按已批准计划执行”等指代无法解析。因此只传入最新正式批准计划一次，同时排除未经批准的建议和历史来源正文。

**把需求变更解析合并进 Worker。** 这能省去一次独立调用，但会让需求状态更新依赖 Worker 的自由文本输出，也不利于单独核对成本和失败状态。可独立审计的解析器使需求更新与 Worker 自由文本输出分离。

## 验收标准

- A/B/C 分别获得稳定身份；修改 B、增加 D 后 A/C 不变，取消 C 只影响 C。
- 修改后的需求不继承旧版本的完成状态或证据。
- 三次完全相同的已结束调用会产生一次提醒，未改变的第四次调用不会进入工具实现。
- 三个相邻失败和结果不变的 `A-B-A-B-A-B` 会触发 Observer；正常的 6、20 或更多 Step 不会仅按长度触发。
- 迟到的 Observer 结果只归档一次，不会用较新的用户纠正重新审查已经完成的旧 Step。
- 新证据、排除关键假设和缩小故障范围即使没有写文件，也应被视为进展。
- 工作已经完成但漏说明时只改写回答；只有工具调用而没有成功结果时不能宣称完成。
- 需求快照变更后进入下一次根 Worker 请求，内容未变且仍被保留时不重复追加，压缩遮蔽后重新注入；原有沙箱和审批链不变。
- 真实执行五分钟且至少产生三个任务工具结果后触发检查；审批等待、执行暂停和 Observer 自身耗时不计入，连续十分钟没有确认进展会暂停。
- 三类辅助调用按真实生命周期位置显示，并可回放输入、Provider 推理、输出、校验失败和用量；Enforce Final Reviewer 位于正式交付之前。
- 确定性检查覆盖输入竞态、真实 Loader 装配行为与 UI 回放；Bundle 默认保持 Shadow。
- 暂停通知回复能够送达用户，但不会恢复工具、完成需求或触发 Agent Loop 的空继续错误。

## 风险

程序生成的整消息引用只能证明是哪条消息触发变化，不能证明模型正确理解语义。Observer 误报可能暂停仍有价值的长调查；五分钟窗口是调用成本与发现延迟之间的显式取舍，不代表能提前发现所有跑偏。Final Reviewer 漏判仍可能放过语义遗漏。在独立评测达到阈值前，Enforce 只用于隔离环境。输入超出预算时安全失败，不能通过丢弃较早需求或证据继续审查。本变更不修改长期记忆、余额、Skill、正式 3080 或桌面启动器。
