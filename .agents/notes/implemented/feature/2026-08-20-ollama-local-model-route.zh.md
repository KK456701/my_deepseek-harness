# Agent Note: 本地 Ollama 模型路由

Status: implemented

[English](2026-08-20-ollama-local-model-route.md) | 中文

## 问题

已部署的 Web 客户端把所有已配置提供方放在同一个列表中。本地 Ollama 路由因此看起来像另一个按量计费的 API 提供方，尽管它经由本机回环服务器运行，并应当能与云端模型一起在输入框中选择。

## 决策

部署配置把 `ollama-local` 声明为使用 Ollama OpenAI 兼容 `/v1` 端点的 `llm-pi-ai` 路由。其目录只包含已安装的对话模型；仅用于 embedding 的模型不作为对话选项。该路由带有一个占位凭据引用，因为共享 OpenAI 适配器即使面对不鉴权的 Ollama 也需要 API key 字段。

模型设置把这个稳定的路由 ID 放在**本地 Ollama 模型**下，其余已配置路由放在**云端 API 模型**下。页面不根据 `baseURL` 推断本地性：云端服务的网关也可以通过本地回环地址暴露。现有的动态会话模型目录已经按提供方分组，因此该路由无需另写一套选择器便会出现在输入框中。

## 考虑过的替代方案

**把每个回环端点都归类为本地。** 这样会给本地代理的云端网关贴上看似合理但错误的标签。

**新增专用 Ollama 提供方适配器。** Ollama 的 OpenAI 兼容端点已能满足已安装的 pi-ai 适配器。再加一个适配器会重复请求处理，且不会增加用户能力。

## 影响

本地模型可以按会话选择，已部署的云端默认模型保持不变。Ollama 服务停止时，选择项仍在，但请求会报告端点失败。本地路由不产生 DeepSeek API 用量；本地推理速度和容量取决于这台电脑与所选模型。

## 测试

Models 设置组件测试固定按路由 ID 的分组。部署验证在暴露路由前检查 Ollama 已安装模型目录及其 OpenAI 兼容端点。
