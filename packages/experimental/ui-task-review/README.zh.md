# @deepseek-ai/dsh-experimental-ui-task-review

[English](README.md) | 中文

简化任务审查流水线的可选浏览器展示。它只消费持久事件，不拥有模型请求、业务决定或第二份对话。

默认 Enforce 路径在普通交付前审查已暂存候选，因此被拒绝草稿只出现在轨迹中，不会成为 Assistant 聊天行。显式启用的旧版交付后 Enforce 仍可以把已展示回答标记为“审查未通过”并折叠；同一 Turn 后续出现新的 Assistant 消息后，标签改为“已被修正版替代”。Shadow 结果以及缺少明确 Enforce 元数据的记录不会重新分类聊天历史。

## 辅助模型轨迹

完整对话测试保留正常对话位置，只有固定材料 Reviewer 筛查使用 evaluation。旧日志缺少输入接收回执不等于 Worker 没有收到输入；验收结果缺失时显示未记录，Turn 结束本身不能证明验收通过。

现有轨迹视图只把三类当前辅助调用显示为 MODEL 行：需求变更解析位于 `before-step`，事件触发的进度检查位于 `after-step`，默认 Enforce 审查位于 `before-delivery`；Shadow 审查仍位于 `after-delivery`。固定材料筛查使用 `scope=evaluation`，不会伪造 USER、TOOL 或 ASSISTANT 事件。只有确实没有 Turn／Step 的记录才进入 `Between turns`。

同一 `callId` 关联已准备请求、真实派发、流式推理或正文、终态响应、程序校验、路由、耗时和报告用量。Provider 暴露的推理以安全纯文本按原语言展示，默认折叠；界面不会声称能读取未公开的内部状态。

请求传输完成与业务校验通过分别展示。超时、取消、JSON 无效和校验失败仍保留已收到输出；只准备但没有派发的请求会明确标记。旧日志缺失的位置、时间或用量保持“未记录”，不推断补造。

旧版需求提取和授权判断记录仍可回放，并显示明确“旧版”标记；新流程不会再生成授权模型行。浏览或回放界面不会增加 token 或用量。

## 模型体验

### 事件派生视图

#### 模型看到的内容

没有新增内容。UI 不增加 `user/message`、`assistant/message`、工具事件或模型可见上下文。

#### Token 影响

没有。展示用量来自持久审计记录。

#### KV Cache 影响

UI 不修改模型请求前缀。

## 已知限制与暂缓事项

- 分页窗口不完整时，匹配的请求或终态可能暂时未加载；继续分页后会按 `callId` 恢复真实关系。
- 没有重复、失败或交替信号的纯语义跑偏，可能直到五分钟真实执行窗口或 Final Reviewer 时才被发现。
