# @deepseek-ai/dsh-client-ui-memory

[English](README.md) | 中文

注册到工作区标题栏的 profile 记忆管理器。“记忆条目”把当前摘要和手册投影为带 revision 的卡片，不是另一份知识库。“记忆文件”区分正式知识、来源证据、显式请求和内部元数据。修改卡片会创建待后续发布的 note。

“立即扫描并整理”只绕过 idle 时间；“归并待处理内容”不执行 discovery。干净重建需要确认，删除派生状态、保留对话，并按用户选择保留或清空显式请求。UI 显示持久化重建进度、失败状态以及 Session 级 use/contribute 控制。

运行参数分别选择提取和归并后端。Codex 调用按次指定模型与推理强度，不修改 Codex 全局配置。干净重建在确认时冻结配置的回看窗口，并由用户选择保留或清空显式请求；两种选择均保留原始对话。参数从后续调用生效，无需重启宿主。

实时外部上下文保护默认关闭。开启后排除含分类调用的整个范围，但不阻断显式记忆请求。编辑器说明允许进入提取的外部证据仍不可信且需要脱敏。

变更记录分别展示对话请求脱敏后的用户原话和模型整理建议。缺少已验证原话时明确显示不可用，不从建议反推原文。处理状态与权威状态继续区分已保存请求和已发布记忆。

卡片正文只展示一次；Task Group heading 只作为卡片标题显示，不改变编辑目标。来源使用分别显示各来源记录的引用次数与最后引用时间，默认显示两个来源。自动来源的范围版本共享 Session 反馈。计数不相加为条目使用总数；零只表示没有可识别 citation，不证明未使用。浏览、注入和普通检索均不增加计数。已提交的引用变更刷新管理界面，不启动模型任务。

## 模型体验

无。此包是可信产品 UI，不贡献模型输入。

#### KV Cache 影响

UI 不贡献 prompt 字节；宿主 Consumer 负责已提交参数和 note 的效果。

## 已知限制与后续工作

- 已发布 Markdown 保持不可变；卡片操作创建结构化 note，并依赖 Phase 2 发布，而不是直接修改文件。
- 旧策略 generation 会明确标记为需要重建，并仅在来源文件视图中可读。
- 记忆根目录、数据库行为和安全容量上限仍由部署配置控制；profile 启用状态与运行参数支持实时修改。
